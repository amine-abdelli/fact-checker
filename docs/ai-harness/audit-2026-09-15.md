# Audit — harness rebuild, 2026-09-15

State of the repository before the rebuild, what was wrong with it, and what was done.

## What was there

- `specs/01-cahier-des-charges.md`…`06` — complete and coherent. Untouched by this rebuild; still the source of truth.
- `CLAUDE.md` — good intentions, wrong map (see below). Rewritten.
- `docs/ai-harness/` — methodology, workflow, agent roster, six prompt-template files, five task briefs.
- `.claude/agents/` — eight sub-agent definitions.
- `prototypes/live_prototype/` — a working FastAPI + Deepgram + LLM extraction prototype.
- `prototypes/ui_prototype/` — a React/Babel iOS mockup, plus a duplicated copy of the specs.

## Problems found

**1. The harness pointed at paths that did not exist.** Every agent and skill file referenced
`r_and_d/src/fact_checker_rd/…` and `r_and_d/server/`. Neither existed. `CLAUDE.md` said to build in
`src/`, which was also absent. An agent following these files would have read nothing and invented
the rest.

**2. Three competing skill systems.** Prompt templates in `docs/ai-harness/skills/`, a Cowork skill
in `docs/ai-harness/skills/cowork/plumb.md`, and the account-level `plumb*` skills — overlapping,
drifting, none of them in `.claude/skills/` where Claude Code actually loads skills. "Skill" meant
three different things depending on the file.

**3. The prototype violated rule 7 and nobody noticed.** `server.py` imported the OpenAI SDK and
`.env.example` asked for `OPENAI_API_KEY`, while its own README and spec said `claude-haiku-4-5`.
Model discipline was written down in four places and enforced in none. This is the strongest
argument for the review step being mandatory rather than optional.

**4. Two product names.** `specs/README.md` says *VeriLive*, everything else says *Plumb*.

**5. Two contradictory product specs.** `specs/plumb-product-spec.md` (mobile-first, iOS) coexisted
with `specs/01-cahier-des-charges.md`–`06` (desktop-first MVP), with `CLAUDE.md` telling agents to ignore the former —
a trap for anything that reads the folder rather than the instructions.

**6. Prototype-shaped specs living next to real ones.** The live prototype's spec sat inside the
prototype folder; the UI prototype folder carried its own duplicate of the six specs, free to drift.

## What was done

- Deleted `prototypes/` entirely — both prototypes — at Amine's request. API keys preserved in
  `.env.keys.bak` at the repo root (not committed). Prototype specs moved to `docs/archive/`.
- Deleted `specs/plumb-product-spec.md`, the superseded mobile draft, and the duplicated spec copies.
- Rebuilt the harness as ten real skills in `.claude/skills/`, each with frontmatter, a spec-reading
  step, explicit contracts and a done-when checklist. Shared references sit in
  `.claude/skills/plumb/references/`.
- Rewrote the eight sub-agents to load their skill and own one path each — no more dead references.
- Added five slash commands for the orchestrator's routine moves.
- Rewrote `CLAUDE.md` around the real state: no code, `src/` empty, three open decisions named
  D-01 to D-03 with what each blocks.
- Rewrote the backlog as `T-000` … `T-106` with checkable acceptance criteria.

## Still open (Amine's calls)

1. `specs/README.md` still says *VeriLive*, and its "open decisions" list is older than `CLAUDE.md`'s.
   Left alone deliberately — the specs are his to amend.
2. D-01, D-02, D-03 are unresolved and block Stage 2, Stage 4b and the whole UI.
3. `specs/06-design-system-ui.md` is written for a mobile iOS layout while the MVP platform is undecided. Whichever way
   D-01 goes, §7 will need a pass.

## Addendum — monorepo restructure (same day)

Amine asked for front and back to be separated, with a third package for a PWA prototype used to
validate recording and real-time claim display before any production code exists.

- `src/` and `tests/` replaced by `packages/prototype-pwa/`, `packages/back/` (pipeline + server)
  and `packages/front/`.
- pnpm workspaces for the JS/TS members (`front`, `back/server`, `prototype-pwa/web`); the Python
  packages keep their own virtualenv.
- New skill `plumb-proto` and agent `proto-engineer`, scoped strictly to the prototype.
- New briefs `T-010`, `T-011`, `T-012`; workflow gains a Phase 0.5 that runs in parallel with the
  research spikes.
- Every path in the harness migrated. The prototype and the production packages are forbidden from
  importing each other — what crosses over is the finding, not the code.
